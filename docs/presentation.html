TELEMETRY PROTOCOL

The LABID Protocol & Port Layer

Zero-allocation, deterministic ASCII framing wire protocol (common/labid) shared identically between C99 firmware and Python host tooling.

Wire Framing Format

$LAB,<TYPE>,<KEY>=<VAL>*<CRC16>\n

Examples:
$LAB,ANNOUNCE,board=idf,uid=E072A1AA2390*5A2F
$LAB,VER,app=1.0.0,git=deded39,slot=0,confirmed=1*E81D
$LAB,STATE,uptime_ms=12400,toggles=12,free_heap=184520*9A14
$LAB,ERR,reason=bad_crc*77C2
  • Zero Malloc: Static buffers, fixed-time parsing, no heap fragmentation.
  • MISRA-Compliant: Verified with GCC -Wall -Wextra -Werror.
  • CRC-16-CCITT: Polynomial 0x1021; shared vectors in test_vectors.json.

Verification & Port Performance

  • Unit Tests: 26 C Unity tests + Python tests passing identical shared vector suite (BL-011, BL-013).
  • Fuzz Robustness: LibFuzzer target ran 10 min clean under ASan/UBSan without a single crash or memory leak (BL-012).
  • Fast Dispatch Latency: Medians 2.7–3.3 ms; 100% queries $\le 4.6$ ms (BL-022).
  • Stress Under Log Flooding: 1,000 consecutive queries with 0 corruption (BL-053).
  • Atomic Print: One-fputs frame output prevents interleaving with FreeRTOS log output.
OTA VERIFICATION

Dual-Transport OTA Flows (WiFi & BLE)

Production verification of both transport paths with live on-target evidence (BL-043, BL-051).

WiFi OTA Sequence (HTTPS Pull)

  1. Host runs ephemeral local HTTPS server serving signed binary on port 8443.
  2. Host dispatches authenticated POST /ota with Bearer token.
  3. Board validates token, responds 202 Accepted, and spawns OTA task.
  4. Board downloads binary over TLS, pinned to Lab Root CA.
  5. esp_ota_end() performs cryptographic signature verification.
  6. Active boot partition switched from ota_0 $\to$ ota_1.
  7. Reboot $\to$ self-test confirms after 5s $\to$ confirmed=True.
  8. Cross-check: LABID VER == HTTPS /version (PLAN §7.3.4).

BLE OTA Sequence (NimBLE Push)

  1. Host scans and discovers nimble-ble-ota peripheral at base MAC+2.
  2. Client negotiates MTU size (up to 512 bytes).
  3. Client transmits START command over Command UUID.
  4. Image split into 4 KB sectors; packets streamed over Data UUID.
  5. Board verifies sector checksums and writes to target OTA slot.
  6. Client transmits STOP command; board calls esp_ota_end().
  7. Board reboots into new slot and validates self-test.
  8. Host queries LABID over serial confirming slot flip and new version.

Negative Security Testing (Cryptographic Gate)

Tested live on hardware: both transports cleanly reject unauthorized or corrupted updates:

  • Foreign-Key Signed Image (BL-026, BL-027): Rejected with Secure boot signature verification failed. Running slot remains unchanged.
  • Unauthorized WiFi Request (BL-052): Wrong or missing Bearer token instantly rejected with HTTP 401 Unauthorized.
  • Corrupted / Truncated Image (BL-052): Checksum mismatch discarded; no reboot; zero downtime.

RISK & TRAPS RETROSPECTIVE

Lessons Learned: 8 Critical Technical Traps

Synthesized in docs/LESSONS_LEARNED.md (BL-063a) to protect the upcoming Zephyr implementation.

1. WSL2 / usbipd Reset Trigger (R14)

Trap: Opening USB serial inside WSL2 asserts DTR/RTS, forcing the ESP32-S3 into ROM bootloader.

Fix: Monitor serial natively on Windows COM14 with DTR/RTS suppressed.

2. Shared sdkconfig Contamination (R15)

Trap: CMake build dirs share a root sdkconfig; variant symbols silently bled across builds.

Fix: Use -DSDKCONFIG=<dir>/sdkconfig and verify output symbols post-build.

3. Optional Subsystem Fatal Asserts

Trap: ESP_ERROR_CHECK on BLE controller failure caused boot loops that killed WiFi recovery.

Fix: Optional subsystems must log errors and fail gracefully, never abort.

4. Polling Starvation

Trap: Dense polling of /version during OTA downloads starved TLS network buffers.

Fix: Poll sparsely ($\ge 2$ s) during active image transfers.

5. Software vs Hardware Resets

Trap: Software resets (esp_restart) keep the USB port alive; waiting for disconnect hung scripts.

Fix: Listen for $LAB,ANNOUNCE or poll endpoint rather than port drop.

6. Vacuous Evidence Pitfalls

Trap: Server-side "bytes served" logged success during TCP RST truncation.

Fix: True proof requires on-target log verification of cryptographic rejection.

7. Octal PSRAM Timing

Trap: Quad PSRAM configuration causes silent corruption on Octal hardware.

Fix: Dedicated bootloader memory test verifies 8 MB AP_3v3 Octal PSRAM.

8. RPi4 Power Brownouts

Trap: RPi4 power dips trip USB write resets during bulk flashing.

Fix: Flashing stays on stable dev workstation; RPi4 limited to OTA dispatch.
