A "run dir" holds `report.json` and `cycles.jsonl` written by `tests_hil/soak_random.py` (look at its `_report` and `_cycle` for the field names).
`cycles.jsonl` lines: one `{"header": plan_id}`, warm-up records with `"cycle": 0`, then one record per cycle (`cycle`, `image`, `kind`, `transport`, `ok`,
`cause`, `duration_s`, optional `infra_retries`, optional `"rerun": true`). A cycle may appear twice (a re-run): the LATEST record wins.

## API
    def load_run(path: Path) -> dict                       # {"report": <report.json>, "cycles": {n: latest record for n >= 1}, "warmup": [...]}
    def summarize(run: dict) -> dict                       # cycles, passes, pass_rate_pct (2 dp), infra_retries (sum), failures [{"cycle","image","transport","cause"}],
                                                           # median_s: {(transport, kind): median duration_s}
    def compare(a: dict, b: dict, tolerance: float = 0.25) -> dict
    def render_markdown(comparison: dict, names: tuple[str, str] = ("board 1", "board 2")) -> str

`compare` returns: `plan_identical` (report["plan"] equal), `cycle_agreement` (None when the plans differ, else
`{"same_outcome": n, "differ": [sorted cycle numbers whose ok flag differs]}`), `duration_diffs` (one entry per (transport, kind) present in both:
`{"transport","kind","a_median","b_median","ratio": b/a,"flagged": abs(ratio-1) > tolerance}`, sorted by (transport, kind)), `summary` ({"a": summarize(a), "b": summarize(b)}),
and `flags`: human-readable strings, in this order: a "plan differs" line if the plans differ; an "outcome differs at cycles [...]" line if any cycle differs;
one "duration: <transport> <kind> is slower/faster on board 2 by NN %" line per flagged diff (use the word "slower" when ratio > 1, else "faster"; "board 2" means b);
a "pass rate" line if the two pass rates differ. Identical runs give an empty list.

`render_markdown`: a heading, the two names, a summary table (pass rate, cycles, infra retries per board), the duration table (transport, kind, medians, ratio,
`FLAG` in the last column when flagged, else empty), and the flags as a bullet list. The words "pass rate" (any case) and "FLAG" must appear as the test expects.
Style: like tests_hil/pool_schedule.py (short docstrings, frozen data where sensible, no restating comments).
