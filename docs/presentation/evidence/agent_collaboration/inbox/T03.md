## plan_sweeps semantics
- All steps of transport 1 (wifi) before any of transport 2 (ble). Within a transport: sweep 1, then sweep 2, ...
- Sweep 1 order = manifest order. Later sweeps: the order of accepted images is REVERSED relative to the previous
  sweep. Reasoning: the board flips slot on every accepted install, so reversing guarantees each image lands on the
  opposite slot in the next sweep for any count. Verify that against the tests rather than trusting this note.
- An image the manifest says the transport accepts -> `expect_accept=True`, `expected_version=entry["version"]`.
- An image the manifest says the transport rejects:
  - role "too_big": one step per transport, sweep 1 only, placed after that sweep's accepting images,
    `expect_accept=False`, `expected_version=None`, `skip=False`.
  - any other role (the BLE-unaligned ones): `skip=True`, `skip_reason` = the manifest's reason for that transport,
    emitted in every sweep, `expect_accept=False`.
- `expected_slot`: running slot starting at `start_slot`, carried across ALL steps in order (wifi then ble).
  Accepted step: flip first, `expected_slot` = new slot. Rejected (`too_big`): `expected_slot` = current unchanged slot.
  Skipped: `None`, and it does not change the running slot.

## classify(step, result)
- `skip` -> "skipped" (result may be None).
- expect_accept: "pass" only if result["accepted"] and result["confirmed"] and result["version"] == step.expected_version
  and result["slot"] == step.expected_slot; else "fail".
- not expect_accept: "expected_reject" if not result["accepted"]; else "fail".

For every manifest image and each transport that ACCEPTS it, both slots 0 and 1 must appear among results whose
`classify` is "pass" (match on image_index + transport; the step's slot is result["slot"]). Return the missing
`(version, transport, slot)` triples, sorted. Results that are not confirmed/accepted do not count.
Hint: results carry `image_index`, `transport`, `accepted`, `confirmed`, `slot`, `version`, `key`.
