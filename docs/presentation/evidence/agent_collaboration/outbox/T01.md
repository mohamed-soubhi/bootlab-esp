## Design notes
- All fields draw from one `shake_256(b"variant:{seed}")` 64-byte stream at fixed non-overlapping offsets
  (pad 0, blink 8, LED r/g/b 16/24/32, pinA 40, pinB 48, trailer 56), so fields are independent.
- Pins: `a = draw[0..n-1]` then `b = draw[0..n-2]`, shifted past `a` when `b >= a` — distinct by construction.
- `led_rgb == (0,0,0)` (p ≈ 2^-24) falls back to `(1,1,1)`.
- `gen_pool(n>13)`: extra `valid` roles spliced in just before the trailing `too_big`, per spec.

## Doubt (not a deviation, flagged for the lead)
Pad bytes are plain uniform draws over `[0, MAX_VALID_PAD]`, since `gen_variant(seed, role)` gets no pool index and
so cannot stratify. Measured margins for the pinned bases are comfortable:

    'spread'       distinct=9/9 span=1946711  trailers=2 distinct
    'bl069-test'   distinct=9/9 span=2048280  trailers=2 distinct
    'a'/'b'/'x'    distinct=9/9 span 1832917..2234665  trailers=2 distinct

But ~0.4% of *arbitrary* seed bases would draw 9 valid pads spanning < 1_000_000. `test_gen_pool_valid_pads_spread`
pins `"spread"` only, so this passes as written. If a later AC5 run picks a fresh seed base, either tell me the base
up front or say the word and I will make the draw index-stratified via `seed_for`'s index.
