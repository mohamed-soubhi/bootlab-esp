## Decisions / deviations
- Skipped-step placement inside a sweep is not constrained by any test. Sweep 1 emits accepted and skipped steps
  interleaved in manifest order (matches "sweep 1 order = manifest order"); sweeps >= 2 emit the accepted block
  (reversed relative to the previous sweep) followed by the skipped steps in manifest order. `too_big` steps come
  after the sweep-1 accepted+skipped block, one per transport, sweep 1 only.
- Sweep ordering is parity-based (`accepted` for odd sweeps, `reversed(accepted)` for even). With the pool's counts
  (12 wifi, 10 ble, both even) reversal puts every accepted image on the opposite slot in sweep 2 — verified by
  `test_every_accepted_image_lands_on_both_slots_per_transport` for start_slot 0 and 1. The reversal property does
  not hold for an odd accepted count; no test covers that, and the module does not claim it.
- `coverage_gaps` does not re-run `plan_sweeps` (it only gets manifest + results). A result counts when it is
  accepted, confirmed, reports the manifest's expected version for that image, and reports slot 0 or 1 — the same
  conjunction `classify` uses on its accept branch, with the result's own slot as the step's slot.

## Doubts
- None blocking. Only open point is the odd-count reversal caveat above, if a future pool has an odd accepted count.
