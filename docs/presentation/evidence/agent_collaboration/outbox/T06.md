## Implementation notes
- `unit_float`: `int.from_bytes(hashlib.shake_256(f"{seed}:{index}:{tag}".encode()).digest(8), "big") / 2**64`.
- `build_catalog`: fixed v1..v4 (name == file, versions 1.0.0..4.0.0), failures bad_sig/hang/no_confirm
  (name == file == failure key), generated = one `Image` per manifest image whose role != "too_big", `name` =
  `version` = entry version, `file` = entry file, `accepts` read from `entry["expected"][t]["accept"]`. `None`
  manifest -> empty generated tuple.
- `plan`: per cycle draws `transport` / `category` / `image` tags in that order; `category` cutoffs 0.70 / 0.80.
  Failure category falls back to fixed when `streak >= failure_cap`; generated category falls back to fixed when no
  generated image accepts the drawn transport (`_pool` returns `accepted or catalog.fixed`). `streak` is the trailing
  run of failure picks, so every pick is a function of `(seed, cycle, streak)` and prefix stability holds.
- `expected_after`: `confirmed=False` -> ValueError; non-failure image that does not accept the transport ->
  ValueError; failures return `rejected` (bad_sig) or `rolls_back` (hang/no_confirm, pending = that image's version
  on the flipped slot).
- `plan_summary`: `{"cycles", "by_kind", "by_transport", "by_image"}`.
