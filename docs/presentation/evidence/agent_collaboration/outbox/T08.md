## Deviations and doubts

1. **`summarize` counts the `cycles` map only, never `warmup`.** The test's `cycles`/`passes`/`pass_rate_pct` come out
   as 6/5/83.33, which matches `report.json` (`total_cycles`/`passes`) because `_report` also filters `cycle >= 1`.
   Warm-up records are therefore loaded and returned but ignored by every statistic. Tell me if a warm-up failure
   should instead surface as a flag.
2. **Zero baseline guard.** `_duration_diffs` uses `_RATIO_UNCOMPARABLE = inf` when `a_median` is 0 (a ratio against
   zero is undefined). That path is unreachable with the current fixtures and would print `inf` in the markdown
   table; if you prefer, a zero baseline could be dropped from `duration_diffs` with a flag instead.
3. **Flag wording is my own.** The test only greps for the substrings `plan`, `outcome`, `slower`, `pass rate`, so
   `"plan differs between the two runs: outcomes and durations are not comparable"`,
   `"outcome differs at cycles [2, 6]"`, `"duration: wifi fixed is slower on board 2 by 50 %"` and
   `"pass rate differs: 100.0 % vs 83.33 %"` satisfy it. Percent is rounded to whole numbers (`:.0f`); a diff just
   over tolerance can render as `0 %`. Change to `:.1f` if you want that visible.
4. **`duration_diffs` is computed even when the plans differ** (the spec only says `cycle_agreement` becomes `None`).
   With a different plan the durations are not really comparable, but the numbers are still reported — the "plan
   differs" flag is the warning. Same for the pass-rate and duration flags, which are still emitted. If a plan
   mismatch should suppress the other flags, that is a one-line change.
5. **`flagged` uses a strict `>`.** `abs(ratio - 1) > tolerance`, i.e. exactly 25 % at `tolerance=0.25` is NOT
   flagged. The test only exercises 50 %, 10 % and 100 %, so it does not pin the boundary; `>=` would flip it.
6. **`load_run` does not validate.** It does not check that cycle numbers are contiguous from 1 and does not raise on
   a foreign plan header, both of which `soak_random._read_records` does. The spec asked for a plain reader, so a
   truncated or mismatched run dir is compared as-is rather than rejected.
7. **Markdown column header is lower-case `flag`**, while the cell text is `FLAG`. The test counts `FLAG`
   (`md.count("FLAG") >= 1`) and only requires `|` and a `"pass rate"` match (`md.lower()`), so both pass; naming the
   header `FLAG` too would still pass, just with a larger count.
