Real Diagnostic Breakthroughs

The 6 Great Engineering War Stories

Real hardware traps, low-level bugs, and permanent architectural defenses

TRAP 01 • WINDOWS BLE

The WinRT GATT Caching Trap

Windows WinRT aggressively caches GATT services across reboots, causing BLE OTA reconnects to fail after partition swaps.

Read War Story →

The Trap: WinRT caches GATT services by MAC address. When MCUboot swaps from v1 to v2, the UUID table changes, but Windows refuses to re-query the device, breaking subsequent transfers.

The Fix: Injected winrt={"use_cached_services": False} into our BleakClient and SMPBLETransport wrapper, forcing fresh service resolution on every connection.

TRAP 02 • SERIAL CONCURRENCY

COM Port Locking (`SharedConsolePort`)

Windows opens COM ports exclusively (`Access is denied`), preventing background loggers from running alongside LABID queries.

Read War Story →

The Trap: Every telemetry query opened and closed the COM port per call. In-between queries, logs were lost—specifically during the crucial esp_ota_end reboot window.

The Fix: Engineered SharedConsolePort: opens the port once, keeps it open, and runs a background thread that tees raw lines to console.log while passing bytes to query handles without collisions.

TRAP 03 • HARDWARE MECHANICS

Software vs. Hardware Reset Behavior

Host test scripts waiting for USB port disconnections hung forever because software reboots don't drop the USB bus.

Read War Story →

The Trap: On ESP32-S3 USB-Serial-JTAG, esp_restart() preserves USB enumeration. Only physical reset buttons drop the bus (~600 ms).

The Fix: Redesigned host detection: tools stop waiting for port drops and instead listen for the atomic $LAB,ANNOUNCE boot frame or poll the HTTPS version endpoint.

TRAP 04 • POWER STABILITY

RPi4 Power Brownouts (`0x50000`)

RPi4 auxiliary runner recorded 7 under-voltage events in 10 minutes (`0x50000`), risking flash block corruption.

Read War Story →

The Trap: Flash memory write peaks during USB flashing cause voltage dips on unpowered RPi4 USB buses, corrupting bootloaders.

The Fix: Strict operational boundary codified in docs/rpi4_limitations.md: heavy builds and USB flashing stay on workstation; RPi4 acts strictly as an OTA network dispatcher over LAN.

TRAP 05 • RADIO COEXISTENCE

Zephyr Radio Coexistence IRQ (BL-064)

Coexistence firmware ran fine, but host writes hung: the board's LABID UART RX interrupt never fired (`irq=0, rx=0`).

Read War Story →

The Trap: In Zephyr build_v2, concurrent Wi-Fi STA and BLE controllers competed for interrupt matrix allocations, starving the USB-CDC UART RX IRQ.

The Fix: Documented full repro in bl064_zephyr_labid_rx_irq_dead.md, safely reflashed target back to verified v1, and isolated IRQ registration order in main.c.

TRAP 06 • TEST RIGOR

The "Vacuous Evidence" Trap

Host image servers reported "all bytes served" during corrupted image tests, creating false proof of firmware rejection.

Read War Story →

The Trap: TCP RST truncation occurred mid-transfer; the board never even parsed the header, but the server counter reported success.

The Fix: Banned server-side counters as acceptance evidence. Every rejection must be proven directly by on-target firmware logs (e.g. Secure boot signature failed) and verified slot stability.

Slide 06 • Wire Protocol

The LABID Zero-Allocation Protocol

Deterministic C99 ASCII framing wire protocol (`$LAB,CMD*CS\n`) shared identically between embedded firmware and host Python CLI.

Zero-Allocation Architecture

• Static buffers only; zero heap allocation on the microcontroller.
• Atomic one-fputs frame writes under console mutex lock.
• Prevents debug printk/ESP_LOG interleaving across 1,000+ queries.

Hardware Telemetry Commands

• ID?: Resolves chip MAC and hardware UID.
• VER?: Queries app version, active partition slot, and confirm state.
• MEASURE: Measures physical LED toggle rate directly from timer ISR.

Slide 10 • Engineering War Stories 1

Bluetooth Caching & Serial Concurrency

Solving real OS-level integration challenges between modern Windows hosts and low-level embedded hardware.

The WinRT GATT Caching Bug

Windows WinRT caches BLE GATT tables by MAC address. When MCUboot swaps firmware slots, Windows fails to see the new GATT table.
Solution: Bypassed WinRT cache with use_cached_services=False.

The Exclusive COM Port Trap

Opening a second serial logger while running a test caused hard permission crashes on Windows.
Solution: Multiplexed console capture and telemetry through a unified thread-safe port seam.

Slide 11 • Engineering War Stories 2

Power Brownouts & Radio Coexistence

Overcoming hardware power limits and complex multi-radio interrupt conflicts on physical silicon.

RPi4 Power Brownouts (`0x50000`)

RPi4 auxiliary host logged persistent under-voltage drops during flash writes.
Solution: Established clear separation: heavy builds/flashes stay on dev workstation; RPi4 handles network OTA only.

Zephyr Radio Coexistence IRQ (BL-064)

On WiFi+BLE coexistence builds, UART RX interrupt never fired (`irq=0, rx=0`).
Solution: Traced interrupt vector conflict, protected board state back to confirmed v1, and isolated driver init ordering.

Slide 12 • Governance & Risk

Strategic Retrospective: R1–R15 Outcomes

Transforming initial project assumptions into verified production realities through disciplined empirical auditing.

Rejecting Vacuous Evidence

Server-side byte counters lie when TCP RST truncates transfers. We mandated that every acceptance pass be proven by on-target firmware logs and post-boot version verification.

The Non-Fatal Subsystem Rule

Optional subsystems (BLE, secondary sensors) must never invoke fatal kernel panics on boot. If a radio fails, the primary recovery path (WiFi OTA) must remain fully alive.
